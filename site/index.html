Tedd.SpanUtils · C# / .NET

A .NET library
for binary data.

Convert numbers, strings, and byte sequences to and from a binary representation. Use it to build network packets, parse file records, or serialize telemetry into a buffer you provide.

The library operates on Span<byte>, ReadOnlySpan<byte>, and Memory<byte>. You define the fields and their order; Tedd.SpanUtils reads and writes each field.

What is it for?

Binary fields in your .NET application.

Use Tedd.SpanUtils when your application needs a specific byte layout. Choose the buffer size and lifetime, then encode or decode the fields in the order required by the format.

The library handles binary representation in memory. Your application supplies the schema and performs socket, file, or other external I/O.

How the cursor moves

The next field starts where the last one ends.

A span describes a contiguous region of memory. A Move method replaces the span variable with the remaining slice: span = span.Slice(bytesConsumed). Its start advances and its length decreases. Only the view changes; the bytes are not shifted in memory.

In this example, 123 occupies four little-endian bytes and unsigned VLQ 300 occupies two bytes. The output cursor advances by six bytes in total.

  1. 0
    Start at offset 0

    output.Length == 32

  2. 4
    Write an Int32 · advance 4 bytes

    output.Length == 28

  3. 6
    Write a VLQ · advance 2 bytes

    output.Length == 26

storage still covers all 32 bytes. output now covers bytes 6–31. Reading the six written bytes advances a separate input cursor from offset 0 to 4, then to 6.

MOVING SPANOffset 0 → 4 → 6
using System;
using Tedd;

Span<byte> storage = stackalloc byte[32];
Span<byte> output = storage;

output.MoveWriteLE(123);       // 28 bytes remain
output.MoveWriteVLQ(300UL);    // 26 bytes remain

int written = storage.Length - output.Length; // 6
ReadOnlySpan<byte> input = storage[..written];

int first = input.MoveReadInt32LE();    // 123; 2 remain
ulong second = input.MoveReadVLQUInt64(); // 300; 0 remain

// input.IsEmpty == true; storage.Length == 32

Choose a cursor model

Direct offsets, moving spans, or stream positions.

All examples use the Tedd namespace. Writers infer the fixed-width type from the argument; readers name it explicitly. LE means little endian; BE means big endian.

01 / Fixed offsets

Read or patch a field at a known offset.

Ordinary methods operate at the beginning of the supplied span and leave that span unchanged. Slice the buffer to select a field. Repeating a read on the same span reads the same field.

Use this model for file headers, packet flags, and fixed record layouts.

FixedOffsets.csC#
using System;
using Tedd;

Span<byte> header = stackalloc byte[8];
header.WriteBE(123);           // Bytes 0–3
header[4..].WriteBE(456);      // Bytes 4–7

int first = header.ReadInt32BE();     // 123
int again = header.ReadInt32BE();     // 123
int second = header[4..].ReadInt32BE(); // 456

// header.Length is still 8; no cursor advances.

02 / Stream position

Serialize a measurement record.

SpanStream retains the full buffer and stores the current byte offset in Position. Each successful operation increments that position by its encoded length.

length: 0 starts an empty writer. Length tracks the written content; Capacity remains the buffer size. Setting Position = 0 rewinds the cursor without clearing content.

MeasurementRecord.csC#
using System;
using Tedd;

Span<byte> record = stackalloc byte[12];
var stream = new SpanStream(record, length: 0);

stream.WriteLE(42L);      // Int64: Position = 8
stream.WriteLE(21.5f);    // Single: Position = 12
                         // Length = 12, Capacity = 12
stream.Position = 0;
long id = stream.ReadInt64LE();       // 42; Position = 8
float value = stream.ReadSingleLE(); // 21.5; Position = 12

// stream.WrittenSpan is the record to pass to file I/O.

03 / Incomplete input

Keep the cursor when a field is truncated.

Use TryMoveRead* when input may end within a field. A failed call returns false and leaves the input cursor unchanged. Failed Try writes also leave the destination bytes unchanged.

Each operation is independent. To parse a whole record speculatively, copy the input span to a local cursor and assign it back only after every field succeeds.

IncompleteField.csC#
using System;
using Tedd;

ReadOnlySpan<byte> input = new byte[] { 0x00, 0x00 };

bool complete = input.TryMoveReadInt32BE(out int value);

// complete == false: Int32 requires 4 bytes.
// input.Length is still 2; its start has not moved.
// Obtain more input before retrying the field.

04 / Payload views

Read a byte payload without copying it.

WriteSized writes a length prefix followed by the payload. ReadSizedReadOnlySpan returns a view of those payload bytes in the existing buffer; it does not allocate an array.

The view shares the buffer's lifetime and observes its changes. Use ReadSizedBytes when a separate array is required. ReadSizedString decodes UTF-8 and allocates the returned string.

PayloadView.csC#
using System;
using Tedd;

Span<byte> packet = stackalloc byte[64];
var writer = new SpanStream(packet, length: 0);
writer.WriteSized(new byte[] { 10, 20, 30 });

var reader = new ReadOnlySpanStream(writer.WrittenSpan);
ReadOnlySpan<byte> payload = reader.ReadSizedReadOnlySpan();

// payload contains 10, 20, 30; reader.Position == 4.
// The prefix occupies 1 byte; the payload occupies 3.
packet[1] = 99;
// payload[0] is now 99: it views the same storage.

05 / Stream integration

Supply memory to a Stream-based API.

MemoryStreamer wraps Memory<byte> and inherits System.IO.Stream. Use it when another API accepts a Stream, or when the backing storage must remain accessible across asynchronous operations.

It has fixed capacity, advances Position, and exposes content as WrittenMemory. The caller owns the backing buffer; disposing the adapter does not dispose that storage.

MemoryAdapter.csC#
using System;
using System.IO;
using Tedd;

byte[] buffer = new byte[64];
using var adapter = new MemoryStreamer(buffer, length: 0);
Stream stream = adapter;
stream.Write(new byte[] { 10, 20, 30 });

ReadOnlyMemory<byte> content = adapter.WrittenMemory;
// content.Length == 3; adapter.Position == 3.
// buffer remains owned by the caller.

Format details: methods without LE or BE generally use native byte order; three-byte integers default to little endian. Signed VLQ uses this library's sign/magnitude convention. Use WriteVInt and ReadVInt for EBML integers. Consult the encoding documentation before implementing interoperability with another format.

Calculation and byte accounting

MB/s = bytes × 1,000 / mean time (ns). A write/read pair counts its encoded data once over the combined time. Bulk rows count one block, not total memory traffic. Integer timings are already normalized per value by BenchmarkDotNet.

VLQ widths are 1, 1, 2, 3, 5, 7, 9, and 10 bytes for the equally weighted inputs. UTF-8 rows include the length prefix.
